## Funkcje i cechy 🎯

- [x] Pełna **architektura MVC**, **przejrzysta struktura** kodu, łatwa w utrzymaniu, wsparcie dla `API` i `interfejsu Web`
- [x] Wsparcie dla **automatycznego generowania przez AI** tekstu wideo, jak również **własnego tekstu**
- [x] Wsparcie dla różnych formatów **wideo HD**
  - [x] Pionowy 9:16, `1080x1920`
  - [x] Poziomy 16:9, `1920x1080`
- [x] Wsparcie dla **masowego generowania wideo**, pozwalające wygenerować wiele filmów naraz i wybrać ten najbardziej satysfakcjonujący
- [x] Wsparcie dla ustawiania **czasu trwania klipów wideo**, co ułatwia regulację częstotliwości zmiany materiałów
- [x] Wsparcie dla tekstów wideo w języku **chińskim** i **angielskim**
- [x] Wsparcie dla **wielu głosów** syntezy z możliwością **odsłuchu w czasie rzeczywistym**
- [x] Wsparcie dla **generowania napisów** z regulacją `czcionki`, `pozycji`, `koloru`, `rozmiaru` oraz ustawieniem `obrysu napisów`
- [x] Wsparcie dla **muzyki w tle** (losowej lub wskazanej z pliku) z możliwością regulacji `głośności muzyki w tle`

## Wymagania sprzętowe 📦

- Zalecany system: Windows 10, macOS 11.0 lub nowszy, bądź popularne dystrybucje Linuksa
- Karta graficzna (GPU) nie jest wymagana, ale jeśli chcesz korzystać z lokalnej transkrypcji, szybszego przetwarzania wideo lub płynniejszego generowania masowego, zalecana jest dedykowana karta graficzna z własną pamięcią VRAM.

| Element | Konfiguracja minimalna | Konfiguracja zalecana | Konfiguracja optymalna |
| ------- | ---------------------- | --------------------- | ---------------------- |
| CPU     | 4 rdzenie              | 6 do 8 rdzeni         | 8 rdzeni i więcej      |
| RAM     | 4 GB                   | 8 GB                  | 16 GB i więcej         |
| GPU     | Niewymagana            | 4 GB VRAM i więcej    | 8 GB VRAM i więcej     |

- Jeśli polegasz głównie na chmurowych modelach LLM, chmurowym TTS i sieciowych źródłach materiałów, procesor (CPU) i pamięć RAM są ważniejsze niż karta graficzna (GPU).
- Jeśli włączysz `faster-whisper`, generowanie masowe lub bardziej wymagające lokalne przetwarzanie, karta graficzna (GPU) znacznie przyspieszy cały proces.

## Instalacja i wdrożenie 📥

### Wymagania wstępne

- Staraj się nie używać **ścieżek zawierających chińskie znaki**, aby uniknąć nieprzewidzianych problemów.
- Upewnij się, że Twoje **połączenie sieciowe** działa prawidłowo. W przypadku korzystania z VPN należy włączyć tryb przekierowania całego ruchu (global traffic).

#### ① Klonowanie kodu

```shell
git clone https://github.com/harry0703/MoneyPrinterTurbo.git
```

#### ② Modyfikacja pliku konfiguracyjnego (opcjonalnie, zaleca się konfigurację w WebUI po uruchomieniu)

- Skopiuj plik `config.example.toml` i nazwij go `config.toml`.
- Postępując zgodnie z instrukcjami w pliku `config.toml`, skonfiguruj `pexels_api_keys` oraz `llm_provider`, a także odpowiedni klucz API dla wybranego dostawcy LLM.
- Jeśli chcesz korzystać z rekomendowanej platformy modeli językowych, możesz ustawić `llm_provider` na `aihubmix` i wprowadzić odpowiedni klucz API.

## Synteza mowy 🗣

Pełną listę obsługiwanych głosów można znaleźć tutaj: [Lista głosów](./docs/voice-list.txt)

Domyślną usługą TTS jest **Edge TTS** (darmowa, nie wymaga klucza API). W interfejsie WebUI jest ona wyświetlana jako **„Azure TTS V1”** – obie nazwy odnoszą się do tej samej darmowej usługi. Możesz ustawić parametr `voice_name` w pliku `config.toml` lub wybrać głos bezpośrednio z listy rozwijanej w WebUI.

> **Uwaga:** Opcje „Azure TTS V1” (Edge TTS, darmowa) oraz „Azure TTS V2” (płatny pakiet Azure Speech SDK) w WebUI to dwie różne pozycje. Tylko wersja V2 wymaga skonfigurowania klucza Azure API Key.

Jeśli chcesz korzystać z wyższej jakości głosów oferowanych przez **Azure TTS V2**, musisz skonfigurować dane uwierzytelniające Azure Speech w pliku `config.toml`:

```toml
[azure]
speech_key = "your-azure-speech-key"
speech_region = "eastus"
```

Azure TTS V2 wymaga aktywnej subskrypcji [Azure Speech Services](https://portal.azure.com/). 9 nowych głosów Azure dodanych w wersji v1.1.2 brzmi ogólnie bardziej naturalnie niż Edge TTS.

## Generowanie napisów 📜

Obecnie obsługiwane są 2 metody generowania napisów:

- **edge**: Używa znaczników czasu zwracanych przez Edge TTS do dopasowania napisów. Metoda jest szybka, nie wymaga karty graficznej (GPU) i działa na zwykłych komputerach, jednak znaczniki czasu dla bardziej skomplikowanych zdań mogą czasami być mniej dokładne.
- **whisper**: Używa lokalnego modelu `faster-whisper` do transkrypcji wygenerowanego dźwięku i tworzy bardziej szczegółowe znaczniki czasu. Proces ten jest wolniejszy (na procesorze CPU zajmuje zazwyczaj od kilku sekund do około 1 minuty, w zależności od rozmiaru modelu) i wymaga pobrania modelu (`large-v3-turbo` ok. 250 MB, `large-v3` ok. 3 GB), ale nie zależy od znaczników czasu dostawcy TTS, co zazwyczaj zapewnia lepszą dokładność napisów.

Możesz zmienić tę opcję, modyfikując parametr `subtitle_provider` w pliku konfiguracyjnym `config.toml`.

Zaleca się rozpoczęcie od trybu `edge`. Jeśli jakość wygenerowanych napisów nie będzie zadowalająca, można przełączyć się na tryb `whisper`.

> Uwaga:

1. Tryb whisper wymaga pobrania pliku modelu z platformy HuggingFace (rozmiar ok. 3 GB). Upewnij się, że masz stabilne połączenie z Internetem.
2. Pozostawienie tego pola pustego oznacza brak generowania napisów.

> Ponieważ dostęp do HuggingFace może być utrudniony w niektórych regionach (np. w Chinach), pliki modelu `whisper-large-v3` można pobrać z alternatywnych źródeł:

Linki do pobrania:

- Dysk Baidu: https://pan.baidu.com/s/11h3Q6tsDtjQKTjUu3sc5cA?pwd=xjs9
- Dysk Quark: https://pan.quark.cn/s/3ee3d991d64b

Po pobraniu modelu należy go rozpakować i umieścić cały katalog w folderze `.\MoneyPrinterTurbo\models`.
Docelowa ścieżka do plików powinna wyglądać następująco: `.\MoneyPrinterTurbo\models\whisper-large-v3`

```
MoneyPrinterTurbo
  ├─models
  │   └─whisper-large-v3
  │          config.json
  │          model.bin
  │          preprocessor_config.json
  │          tokenizer.json
  │          vocabulary.json
```

## Często zadawane pytania (FAQ) 🤔

### ❓RuntimeError: No ffmpeg exe could be found

Zazwyczaj program ffmpeg jest pobierany i wykrywany automatycznie.
Jeśli jednak w Twoim środowisku wystąpią problemy uniemożliwiające automatyczne pobranie, możesz napotkać następujący błąd:

```
RuntimeError: No ffmpeg exe could be found.
Install ffmpeg on your system, or set the IMAGEIO_FFMPEG_EXE environment variable.
```

W takim przypadku możesz pobrać ffmpeg ze strony https://www.gyan.dev/ffmpeg/builds/, rozpakować go, a następnie ustawić parametr `ffmpeg_path` na rzeczywistą ścieżkę instalacji.

```toml
[app]
# Skonfiguruj zgodnie z rzeczywistą ścieżką. Pamiętaj, że separatorem ścieżki w systemie Windows jest \\
ffmpeg_path = "C:\\Users\\harry\\Downloads\\ffmpeg.exe"
```

### ❓Błędy związane z ImageMagick

> **Obecna wersja nie wymaga już programu ImageMagick.**
>
> Po aktualizacji projektu do wersji **MoviePy 2.x**, renderowanie napisów zostało zmienione na bibliotekę **Pillow** i nie zależy już od ImageMagick. Jeśli nadal widzisz błędy związane z ImageMagick, zazwyczaj oznacza to, że uruchamiasz starszą wersję kodu. Wykonaj polecenie `git pull`, aby zaktualizować kod (użytkownicy systemu Windows mogą również uruchomić plik `update.bat`).

### ❓OSError: [Errno 24] Too many open files

Ten problem wynika z limitu liczby otwartych plików w systemie operacyjnym. Można go rozwiązać, zwiększając ten limit.

Sprawdzenie aktualnego limitu:

```shell
ulimit -n
```

Jeśli limit jest zbyt niski, możesz go zwiększyć, na przykład:

```shell
ulimit -n 10240
```
